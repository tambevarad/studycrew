**User story:** As a member, I can add agenda items and flag topics I need help with before a meeting.

## Files you own

`src/server/services/agenda/**`, `src/app/api/v1/teams/[teamId]/meetings/[meetingId]/agenda/**`,
`src/components/features/agenda/**` (**keep** `export function MeetingAgenda({ teamId, meetingId })` — may become async),
tests `agenda*`.

## Build

- Service: `listAgenda(teamId, actorId, meetingId)` sorted by `helpCount` desc then `createdAt`; `addAgendaItem`
  (`AGENDA_ITEM_ADDED`); `setHelpFlag(itemId, { needsHelp })` (idempotent per member); `deleteAgendaItem` (author or leader).
  Meeting must belong to the team (404).
- UI on the meeting page: "Agenda" card, add-topic input, each item shows title, notes, author, "🙋 3 need help" count
  with a toggle button "I need help with this" (`aria-pressed`), sorted live. Empty: "Add topics so everyone comes prepared."

## Acceptance criteria

- AC1: Items are sorted by how many members flagged them.
- AC2: A member can flag/unflag once; counts update.
- AC3: Only author or leader can delete; meeting from another team → 404.

## Required tests

Integration for routes (AC1–AC3); E2E on the seeded meeting.

## Implementation notes (owner fills in)

- `MeetingAgenda` keeps its export and props and is now an async Server Component: it loads the topics and passes them to the
  client `AgendaCard`. No dates are shown, so nothing is formatted in client render.
- `getMeeting` from PB-06's service does the membership check and the "meeting belongs to this team" 404 (AC3). A topic that
  belongs to a different meeting is also a 404.
- `setHelpFlag` uses `createMany` with `skipDuplicates`, so simultaneous requests from one member still count once (AC2).
- The list re-sorts when the server re-reads it after a flag. That moves the button in the DOM and would drop keyboard focus,
  so `AgendaCard` puts focus back on it (checked in `agenda.cy.ts`).
- The toggle's accessible name is "I need help with this: <topic>", so each button is distinct and still contains the visible
  text (the rule behind D-05). The visible label doesn't change; the pressed state shows through `aria-pressed`, a check mark,
  and the button style.
- Sorting uses Prisma's order by relation count. The contract has no `canDelete`, so the card works it out from `me`; the
  service enforces it anyway.
- As `api.md` says, only adding a topic logs activity. Flags and deletes don't, and nothing sends notifications.
