**User story:** As a team, we have a 30-case labeled test set and an AI evaluation report.

## Files you own

`tests/ai-eval/**`, `scripts/ai-eval.ts`, `docs/ai-eval-report.md`, `docs/ai-log/PB-16.md`. (Adding the script entry
`"ai:eval": "tsx scripts/ai-eval.ts"` to `package.json` is pre-approved — mention it in the PR.)

## Build

- 30 cases in `tests/ai-eval/cases/NN-<slug>.json` across 5 subjects (6 each) and all four work types:
  `{ id, subject, workType, instructions, draft, expected: [{ requirementHint, status }] }` with **seeded gaps**
  (requirements deliberately missing or thin). Write them by hand; if AI helps draft them, a human labels every expected status.
- `scripts/ai-eval.ts`: runs each case through `runCoverageCheck`'s model + verification path with the configured real
  provider (never in CI), matches predicted items to expected by keyword overlap of `requirementHint`, and outputs:
  **Missing recall** (target ≥ 0.85), **Missing precision** (≥ 0.80), **quote verification rate** (≥ 95%),
  **p95 latency** (≤ 30 s), cost estimate, per-case table → `tests/ai-eval/results/<date>-<promptVersion>.json`.
- `docs/ai-eval-report.md`: method, dataset description, results table, confusion matrix, error analysis (≥ 5 examples
  of misses/hallucinations), helpfulness % from PB-11 ratings, limitations, prompt-version history, next steps.
- Weekly re-run with versioned prompts (risk R-02).

## Acceptance criteria

- AC1: 30 labeled cases, 5 subjects, seeded gaps documented.
- AC2: One command produces the metrics file and the numbers in the report match it.
- AC3: The report states whether each target was met and what changed between prompt versions.

## Implementation notes (owner fills in)

- `tests/ai-eval/lib.ts` holds all the logic and has no I/O, so `tests/unit/ai-eval.test.ts` pins it with fixed inputs. That
  test file sits outside this task's list because Vitest only picks up `tests/unit/`. It also checks the dataset (AC1), that
  each results file's metrics follow from its own runs, and that the report's tables match them exactly (AC2/AC3).
- `scripts/ai-eval.ts` uses the real `SdkCoverageModel`, prompts, `alignItems`, and `verifyItems`, without a database. It wraps
  the language model with AI SDK middleware so cost comes from actual tokens. It refuses to run in CI or under Vitest, and it
  never overwrites a results file (a repeat becomes `-run2`).
- Provider is Claude (`AI_PROVIDER=claude`, `claude-haiku-5-5`), not OpenAI as first planned. The key comes from `.env.local`.
- Matching has its own stemmer, because the mock's treats `side` and `sides` as different words. `STOPWORDS` is now exported
  from `src/server/ai/mock-model.ts` (PB-10's file) so the list isn't copied.
- Each case has an extra `notes` field documenting what was seeded (AC1).
- Result: all targets met on prompt v1 in two runs, so no prompt revision was needed. See `docs/ai-eval-report.md`.
- **Open:** the labels are AI-drafted and need Devarsh's check. Helpfulness has no data yet (n = 0).
