## Build

**Service** `src/server/services/tasks/service.ts` — ★ exported for PB-11/12/13, keep these signatures:
- `export const taskInclude` (Prisma include for assignees + createdBy + coverageItem id) and
  `export function toTaskDTO(row, now = new Date()): TaskDTO` (`isOverdue = dueAt < now && status !== DONE`).
- `listTasks(teamId, actorId, query): Promise<TaskDTO[]>` — ordered by status order, then position.
- `getTask(teamId, actorId, taskId)` — 404 if not in this team.
- `createTask(teamId, actorId, input): Promise<TaskDTO>` — position = (max position in column) + 1000; assignees must be
  members (`assertAllMembers`); milestone must belong to the team; `completedAt` if created as DONE.
  Activity `TASK_CREATED`; notify `TASK_ASSIGNED` to assignees except actor.
- `updateTask(teamId, actorId, taskId, input)` — replaces assignee set when `assigneeIds` given; newly added assignees get
  `TASK_ASSIGNED` notify + `TASK_ASSIGNED` activity; otherwise `TASK_UPDATED` (summary names what changed: "changed the due date of “X”").
- `deleteTask(teamId, actorId, taskId)` — `TASK_DELETED`.
- `moveTask(teamId, actorId, taskId, { status, index })` — compute the new position from neighbours in the target column
  (excluding the moved task): before first → first − 1000; after last → last + 1000; between → midpoint. If the gap
  < 0.001, renumber that column (1000, 2000, …) in the same transaction. Entering DONE sets `completedAt` + activity
  `TASK_COMPLETED`; leaving DONE clears it; otherwise `TASK_MOVED` ("moved “X” to Review"). Same-column reorder logs nothing.
- Pure `positions.ts`: `positionForIndex(sortedPositions: number[], index): { position: number; needsRebalance: boolean }` (unit-tested).

**Routes** exactly as `api.md` § PB-05, all with `teamRoute`.

**Page** `/teams/[teamId]/board` (`SectionHeader` "Task board", action **New task**)
- Server Component loads `listTasks` + team members (for assignee pickers) and passes to a client `TaskBoard`.
- Four columns (To Do, In Progress, Review, Done) with counts. Cards: title, priority badge (High = danger, Medium =
  warning, Low = neutral), due label via `dueLabel()` (overdue in `danger` text with "Overdue" word, due within 24 h in
  `warning`), assignee `AvatarStack`.
- **Drag and drop** with dnd-kit (between and within columns) → optimistic update → `POST …/move` → on error revert + toast.
- **Keyboard alternative (required):** each card has a "Move to…" menu (status + "Top/Bottom"), and dnd-kit's
  KeyboardSensor is enabled with announcements.
- Filters bar: "All / Assigned to me", priority, text search (client-side).
- New/edit task `Dialog`: title, description, status, priority, due date+time (viewer's timezone → ISO), assignees
  (checkbox list of members), milestone (select; hidden if none). Delete in the edit dialog with `ConfirmDialog`.
- `?task=<id>` in the URL opens that task's dialog (notifications link here).
- Empty column: muted "Nothing here yet"; empty board: `EmptyState` "Create your first task".

## Acceptance criteria

- AC1: Creating a task with title, assignees, due date, and priority puts it at the bottom of To Do, logs activity, and notifies assignees (not me).
- AC2: Dragging a card to Done marks it complete (`completedAt` set, activity "completed …"); dragging it back clears `completedAt`.
- AC3: Reordering within a column persists after reload.
- AC4: Moving to index 0, the middle, and the end of a column produces strictly increasing positions; tight gaps trigger a rebalance.
- AC5: Assigning a non-member returns 400; a task id from another team returns 404.
- AC6: Editing assignees notifies only newly added people.
- AC7: Overdue tasks show "Overdue" in red; due-within-24h in amber.
- AC8: Every action is possible with the keyboard ("Move to…" menu).
- AC9: Non-members get 403 on every route (sweep) and the page shows no tasks.
- AC10: No serious/critical axe violations on the board and the dialog.
