**User story:** As a student, I can paint my weekly availability on a grid so my team can find meeting times.

## Contracts

`src/contracts/availability.ts`: slot encoding `slot = day * 48 + halfHour` (Mon = 0, in the **user's** timezone),

## Build

**Service** `src/server/services/availability/service.ts`
- `getMyAvailability(userId): Promise<AvailabilityDTO>` — empty slots + `updatedAt: null` if never saved.
- `setMyAvailability(userId, input): Promise<AvailabilityDTO>` — upsert; de-duplicate + sort.
- Pure helpers in `grid.ts` (unit-tested): `toggleRange(slots, fromSlot, toSlot, mode: "add"|"remove")` for rectangle
  painting (all days between, all half-hours between), `slotsToRanges(slots)` → `[{day, start:"18:00", end:"22:00"}]`
  for a text summary, `copyDay(slots, fromDay, toDays[])`.

**Routes** `GET/PUT /api/v1/me/availability` (`authedRoute`), `GET /api/v1/teams/[teamId]/availability` (`teamRoute`).

**Page** `/availability` (`PageHeader` "My availability", description "Times are in your time zone: America/Chicago ·
Change in Profile")
- Grid: 7 day columns × half-hour rows. Default visible range 07:00–24:00 with a "Show all hours" toggle.
  Hour labels every hour on the left.
- **Painting:** mouse/pointer down on a cell starts a rectangle; mode is *add* if the first cell was empty, *remove* if
  it was filled; drag paints; pointer up commits. Touch works via pointer events.
- **Keyboard (required, NFR-03):** grid is `role="grid"`, cells are `role="gridcell"` with `aria-selected`, arrow keys
  move focus, Space toggles, Shift+arrows extends a selection, Enter applies. Visible focus ring.
- Quick actions: "Copy Monday to weekdays", "Clear all" (ConfirmDialog), presets "Weekday evenings (6–10 pm)".
- Unsaved changes: sticky "Save availability" bar with count of changed cells; warn on navigation away
  (`beforeunload`). Save → toast "Availability saved".
- Text summary under the grid using `slotsToRanges` ("Mon 6:00 PM–10:00 PM, …") — a non-visual equivalent of the grid.
- Colors: available = `success` tokens; focus = `brand`.

## Acceptance criteria

- AC1: Given an empty grid, when I drag from Mon 18:00 to Wed 21:30 and save, then those 3 × 8 = 24 slots are stored.
- AC2: When I start a drag on a filled cell, then the drag removes slots instead of adding.
- AC3: Using only the keyboard I can select and save availability.
- AC4: Saving twice with the same slots is idempotent; duplicates in the request are removed and the result is sorted.
- AC5: Slots outside 0–335 or > 336 entries → 400.
- AC6: `GET /api/v1/teams/:teamId/availability` returns every member with their timezone and slots; non-members get 403.
- AC7: The page shows which timezone the grid uses and links to the profile to change it.
- AC8: No serious/critical axe violations.

## Implementation notes (owner fills in)

**Built (Oct 22, Krish + Claude Code):**

- **Service** `src/server/services/availability/service.ts`: `getMyAvailability` (empty + `updatedAt: null` if never
  saved), `setMyAvailability` (upsert; de-dupe + sort; idempotent), `getTeamAvailabilityFor` (membership check, then the
  shared `getTeamAvailability` reader).
- **Routes** `GET/PUT /api/v1/me/availability` (`authedRoute`), `GET /api/v1/teams/[teamId]/availability` (`teamRoute`).
- **Pure helpers** live in `src/components/features/availability/grid.ts` rather than under `services/`, because the
  painting, copy-day, preset, and summary logic runs in the browser and client code may not import `src/server/**`. The
  service only needs de-dupe + sort. Helpers: `toggleRange`, `slotsToRanges` (a range reaching midnight ends at
  "24:00"), `copyDay`, `weekdayEvenings`, `countChanged`, `formatRange`, `to12h`.
- **Page** `/availability`: `PageHeader` with "Times are in your time zone: … · Change in Profile". 7 × 48 grid
  (07:00–24:00 by default, "Show all hours" toggle). Pointer painting (mouse, pen, touch via pointer events;
  `touch-action: none` on the grid) with add/remove mode from the first cell and a live preview. Keyboard:
  `role=grid` with a roving tabindex, `aria-selected` cells labelled "Monday 6:00 PM to 6:30 PM", arrows move,
  Home/End jump to Monday/Sunday, Space toggles, Shift+arrows selects a block, Enter fills or clears it, Esc cancels.
  Quick actions: Copy Monday to weekdays, Weekday evenings (6–10 pm), Clear all (`ConfirmDialog`). A sticky bar shows
  "N unsaved changes" with Save / Discard; `beforeunload` warns when leaving with unsaved changes. A text summary under
  the grid is the non-visual equivalent. Available = `success-600`, selection = `brand`.

**Decisions / gotchas:**

- The live drag is kept in a **ref** (state only drives the preview), and the pointer-up listener is registered
  once. With state only, pointer events that arrived before React re-rendered saw a stale `null`: fast drags lost their
  first moves and a quick tap could leave the grid stuck in preview. Found while debugging the Cypress spec.
- Cypress's `trigger()` pointer events didn't carry the data the grid reads on move, so `availability.cy.ts`
  dispatches real `PointerEvent`s at each cell's centre (after scrolling it into view).
- The spec restores Krish's seeded availability after each test so PB-06's meeting finder sees the seed.
- `beforeunload` covers closing or reloading the tab; in-app link clicks (Next client navigation) don't trigger it.

**Tests:** `tests/unit/availability-grid.test.ts` (rectangles in any direction, remove mode, ranges incl. 24:00,
copyDay, presets, change count), `tests/integration/availability.test.ts` (AC1, AC4–AC6, 401), `cypress/e2e/availability.cy.ts`
(mouse paint + erase + save + reload, keyboard selection + save, quick actions, time-zone header, axe).
