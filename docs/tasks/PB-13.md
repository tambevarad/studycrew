**User story:** As a member, I can create milestones from templates or by hand, link tasks to them, and see progress.

## Files you own

`src/server/services/milestones/**`, `src/app/api/v1/teams/[teamId]/milestones/**`,
`src/app/(app)/teams/[teamId]/milestones/**`, `src/components/features/milestones/**`, tests `milestones*`.

## Build

- Service: `listMilestones` (ordered by `position`, with `taskCount`, `doneCount`, `percent`), `createMilestone`,
  `applyTemplate({ templateKey, finalDueAt })` (creates the template's milestones with due dates spread evenly from now
  to `finalDueAt`, appended after existing ones), `updateMilestone`, `deleteMilestone` (tasks keep existing, `milestoneId`
  set null by FK), `linkTask(milestoneId, taskId)` via PB-05 `updateTask(…, { milestoneId })`. Activity types per `api.md`.
- Pure `progress.ts`: `percent(done, total)`; `spreadDueDates(count, from, to)`.
- Page: milestone list as cards with progress bars (`success` fill + "3 of 5 tasks done" text), due date (overdue in
  danger), linked tasks list with status badges, "Link a task" select, **Use a template** dialog (pick template, final
  due date, preview of milestones before creating), manual create/edit/delete (ConfirmDialog).

## Acceptance criteria

- AC1: Applying the "Presentation" template with a final date creates 5 milestones with increasing due dates ending on that date.
- AC2: Linking 4 tasks of which 1 is DONE shows 25%.
- AC3: Deleting a milestone keeps its tasks (unlinked).
- AC4: Templates show a preview before creating; no serious/critical axe violations.

## Required tests

Unit for `spreadDueDates` and `percent`; integration for routes (AC1–AC3); E2E: apply template, link a task, see %.
