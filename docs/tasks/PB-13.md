# PB-13 Milestones and templates

**User story:** As a member, I can create milestones from templates or by hand, link tasks to them, and see progress.

## Files you own

`src/server/services/milestones/**`, `src/app/api/v1/teams/[teamId]/milestones/**`,
`src/app/(app)/teams/[teamId]/milestones/**`, `src/components/features/milestones/**`, tests `milestones*`.

## Build

- Service: `listMilestones` (ordered by `position`, with `taskCount`, `doneCount`, `percent`), `createMilestone`,
  `applyTemplate({ templateKey, finalDueAt })` (creates the template's milestones with due dates spread evenly from now
  to `finalDueAt`, appended after existing ones), `updateMilestone`, `deleteMilestone` (tasks keep existing, `milestoneId`
  set null by FK), `linkTask(milestoneId, taskId)` via PB-05 `updateTask(…, { milestoneId })`. Activity types per `api.md`.
- Pure `progress.ts`: `percent(done, total)`; `spreadDueDates(count, from, to)`.
- Page: milestone list as cards with progress bars (`success` fill + "3 of 5 tasks done" text), due date (overdue in
  danger), linked tasks list with status badges, "Link a task" select, **Use a template** dialog (pick template, final
  due date, preview of milestones before creating), manual create/edit/delete (ConfirmDialog).

## Acceptance criteria

- AC1: Applying the "Presentation" template with a final date creates 5 milestones with increasing due dates ending on that date.
- AC2: Linking 4 tasks of which 1 is DONE shows 25%.
- AC3: Deleting a milestone keeps its tasks (unlinked).
- AC4: Templates show a preview before creating; no serious/critical axe violations.

## Required tests

Unit for `spreadDueDates` and `percent`; integration for routes (AC1–AC3); E2E: apply template, link a task, see %.

## Implementation notes (owner fills in)

**Built (Nov 1, Varad + Claude Code):**

- **Service** `src/server/services/milestones/service.ts`: `listMilestones` (position order, `taskCount`, `doneCount`,
  `percent`), `createMilestone`, `applyTemplate`, `updateMilestone`, `deleteMilestone`, `linkTask`. Writes only
  `milestone`; linking goes through PB-05 `updateTask(…, { milestoneId })`, which also checks the task is in this team
  (404) and logs TASK_UPDATED. Activity: MILESTONE_CREATED (one per template milestone, "… from the Presentation
  template"), MILESTONE_UPDATED ("renamed … to …" when the title changes), MILESTONE_DELETED.
- **Pure rules** `src/components/features/milestones/progress.ts` (shared with the template preview, like PB-06's
  `calendar-dates.ts`): `percent`, `spreadDueDates(count, from, to, timeZone)`, `endOfDayIso`, `dateInputValue`.
  Template dates: the last is exactly the final date; when there is at least a day per milestone the others are whole
  days before it at the same wall-clock time in the actor's zone (DST-safe), otherwise evenly to the minute.
  A final date that isn't in the future → 400 "Pick a final due date in the future."
- **Routes** exactly as `api.md` § PB-13 (GET/POST, apply-template, PATCH/DELETE, POST …/tasks), all `teamRoute`.
- **Page** `/teams/[teamId]/milestones`: cards with due date (danger "Overdue: was due …" when past and not finished),
  description, a progress bar (`role=progressbar`, text "3 of 5 tasks done" + %), linked tasks with status badges and an
  **Unlink** button, a **Link a task** select (tasks in another milestone say they will move). **Use a template** dialog
  shows every milestone with its date before anything is created (AC4); New / Edit dialog; delete with ConfirmDialog
  saying how many tasks stay on the board (AC3). Empty state: "Start from a template".

**Decisions / gotchas:**

- Unlinking is a task edit, so the page calls PB-05's `PATCH /tasks/:id { milestoneId: null }` instead of adding a route.
- Due dates are days: the date input means 11:59 pm that day in the viewer's zone. Dates render with the
  `formatToParts` helpers from PB-06 (`meetings/format.ts`) to avoid the Node vs Chrome hydration mismatch.
- Dialogs mount only while open (shared `Dialog` heading id).
- For PB-12: `listMilestones(teamId, actorId)` returns `MilestoneDTO[]` with `percent`, ready for a dashboard card.

**Tests:** `tests/unit/milestones.test.ts` (percent, spreading incl. across the Nov 1 DST change and short spans, date
round trips), `tests/integration/milestones.test.ts` (AC1–AC3, ordering after existing milestones, moving a task between
milestones, other-team 404s, 403/401, all routes and validation), `cypress/e2e/milestones.cy.ts` (seeded 50%, template
preview → create 5, link/unlink updates %, delete keeps the task on the board; axe on the page and the dialog).
