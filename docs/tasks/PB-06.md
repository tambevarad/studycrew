## Build

**Pure meeting finder** `src/server/services/meetings/meeting-finder.ts` (most of the points; test-first — risk R-04)

```ts
export interface FinderMember { userId: string; timezone: string; slots: number[] }
export interface BusyInterval { startsAt: Date; endsAt: Date }
export function suggestMeetingTimes(args: {
  members: FinderMember[];
  viewerTimeZone: string;
  from: string; to: string;          // YYYY-MM-DD in viewer tz, inclusive
  durationMinutes: number;           // multiple of 30
  earliestHour: number; latestHour: number; // window in viewer tz
  busy: BusyInterval[];              // existing team meetings — overlapping candidates are excluded
  limit: number;
  now?: Date;                        // candidates must start after now
}): MeetingSuggestionDTO[];
export function weekHeatmap(members: FinderMember[], weekStartDate: string, viewerTimeZone: string): number[]; // 336 counts in viewer-tz slots
```

- Candidates: every 30 minutes from `earliestHour` to `latestHour − duration` on each date in the viewer's tz.
- A member is available for a candidate iff every 30-minute cell it covers, converted to **that member's** local
  weekday + half-hour (use `TZDate` from `@date-fns/tz`), is in their slots.
- Rank: `availableCount` desc, then earliest start. Return top `limit`. Members with no slots count as unavailable.
- Must be correct across the **Nov 1, 2026 DST change** and for members in different US time zones.

## Acceptance criteria

- AC1: With 4 members whose availability overlaps Thu 7–8 pm (Chicago), the finder ranks that slot first with 4/4.
- AC2: A member in New York with 8–9 pm Eastern free is available for 7–8 pm Central (cross-timezone).
- AC3: Suggestions on Sun Nov 1 / Mon Nov 2, 2026 are correct across the DST change (unit test with fixed dates).
- AC4: A slot overlapping an existing team meeting is not suggested.
- AC5: Creating a meeting shows it on the calendar and notifies the other members; RSVP updates counts.
- AC6: End before start → 400 with "End time must be after the start…"; only creator or leader can edit/delete (403).
- AC7: Meeting times display in the viewer's timezone.
- AC8: The heatmap has a text alternative; page has no serious/critical axe violations.
- AC9 (NFR-01): suggestions for 8 members over 14 days return in < 300 ms (unit benchmark-style assertion).

## Implementation notes (owner fills in)

- **Change from the proposal: FullCalendar is not used.** The installed FullCalendar core is v6, which only shows
  a named time zone (e.g. America/Chicago) correctly with an extra plugin (Luxon or moment-timezone). The no-new-dependencies
  rule ruled that out. Instead there is a small custom week view (`week-view.tsx`) that renders in the viewer's zone with
  `@date-fns/tz`, and it can draw the When2meet-style heatmap directly behind the meetings, which FullCalendar could not.
  The package stays installed (removing it needs a contract change); recorded for progress report §1.
- **Finder** (`meeting-finder.ts`, pure): generates 30-minute-aligned candidates in the viewer's zone and, for every
  30-minute cell, converts the instant into each member's own zone to look up their weekday/half-hour slot. Tested
  across US DST (Nov 1, 2026) and UK DST (Oct 25) with a Chicago + London pair, and cross-zone with New York.
  Existing team meetings are treated as busy. Overlapping candidates for the same people are collapsed so one long free
  block doesn't fill the list. 8 members × 14 days runs well under 300 ms.
- **Date helpers** (`components/features/meetings/calendar-dates.ts`) are pure and shared by the server finder and
  the client week view. Calendar-date maths uses UTC on `YYYY-MM-DD`, so DST never shifts a date.
- **Service**: organizer RSVPs "Going" automatically; edits/cancels are organizer-or-leader; partial time edits are
  re-validated (the contract refine can only see both fields together). Notifications include the time with a zone
  abbreviation ("Thu, Oct 29, 7:00 PM CDT") because they go to everyone. RSVP activity is logged only when the answer changes.
- **Accessibility**: heatmap cells are decorative (`aria-hidden`) with a text alternative ("Best times this week" plus
  hover titles). Keyboard users schedule with *New meeting* / *Find a time*. Meeting blocks are links whose accessible
  name starts with the visible text. The RSVP colours use the -700 shades to pass 4.5:1.
- Tests: `tests/unit/meeting-finder.test.ts` (12), `tests/integration/meetings.test.ts` (11), `cypress/e2e/calendar.cy.ts` (3).
  Screenshots: `docs/screenshots/PB-06-*.png`.
