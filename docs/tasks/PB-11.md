# PB-11 Turn an AI suggestion into a task, and rate it

| Owner            | Sprint | Points | Covers                          | Priority | Depends on                                                               |
| ---------------- | ------ | ------ | ------------------------------- | -------- | ------------------------------------------------------------------------ |
| Varad Tambe (M1) | 4      | 3      | FR-07, PB-16 helpfulness metric | Must     | PB-05 merged (`createTask`), PB-10 merged (report page renders the slot) |

**User story:** As a member, I can turn an AI suggestion into an assigned task in one click and rate whether it helped.

## Files you own

`src/server/services/coverage-actions/**`, `src/app/api/v1/teams/[teamId]/coverage-items/**`,
`src/components/features/coverage-actions/**` (**keep** `export function CoverageItemActions({ teamId, item })`),
tests `tests/integration/coverage-actions*.test.ts`, `cypress/e2e/coverage-actions*.cy.ts`.

## Build

- `createTaskFromItem(teamId, actorId, itemId, input)`: item must belong to a report of this team (else 404); 409 if
  `item.taskId` set; call PB-05 `createTask(teamId, actorId, { title: item.suggestion ?? item.requirement, description:
"From AI Coverage Check “<report title>”: <requirement> — <reason>", priority: MISSING ? "HIGH" : "MEDIUM", assigneeIds,
dueAt })`, then set `coverageItem.taskId` right after (two services, so not one transaction; the unique index on
  `taskId` plus a conditional update `where: { id, taskId: null }` turns a double click into a 409). Activity `COVERAGE_TASK_CREATED`.
- `rateItem(teamId, actorId, itemId, { rating })` → sets `rating`, `ratedById`; returns `CoverageItemDTO`.
- Routes: `POST …/coverage-items/[itemId]/task`, `PUT …/coverage-items/[itemId]/rating` (`teamRoute`).
- UI (`CoverageItemActions`, client): for non-covered items a **Create task** button → small dialog (assignees checklist,
  due date) → success toast with "View on board" link; once created shows "Task created → open". Thumbs up/down toggle
  buttons (`aria-pressed`, labels "Helpful" / "Not helpful"). The slot only receives `teamId` + `item`, so load the member
  list with `GET /api/v1/teams/:teamId` (PB-04) when the dialog opens.

## Acceptance criteria

- AC1: Clicking Create task on a Missing item creates a High-priority task in To Do with the suggestion as title and links it to the item; a second attempt → 409 "A task already exists for this suggestion."
- AC2: The new task appears on the board and assignees are notified (via PB-05).
- AC3: Rating saves and can be changed; the evaluation report can compute % helpful.
- AC4: Items from another team's report → 404; non-members → 403.

## Required tests

Integration for both routes (AC1–AC4); E2E: run a check → create task → see it on the board.

## Implementation notes (owner fills in)

**Built (Nov 1, Varad + Claude Code):**

- **Service** `src/server/services/coverage-actions/service.ts`: `createTaskFromItem` and `rateItem`, exactly as specced.
  The item is loaded with its report and must belong to this team (else 404, AC4); membership first (403). The task is
  created through PB-05's `createTask` (so TASK_CREATED activity and TASK_ASSIGNED notifications come from PB-05, AC2),
  then linked with a conditional `updateMany({ where: { id, taskId: null } })`. If that matches nothing, a parallel
  request won: this request deletes its own task through PB-05's `deleteTask` and returns the same 409 as a later
  attempt, so a double click never leaves an orphan task. Activity `COVERAGE_TASK_CREATED` on the report.
- **Text rules** (`text.ts`, pure): title = suggestion, else the requirement, whitespace collapsed and cut at a word
  to fit the 200-character task title; description "From AI Coverage Check “Title”: requirement — reason".
  Missing → High priority, Partial → Medium.
- **Routes** `POST …/coverage-items/[itemId]/task` (201) and `PUT …/coverage-items/[itemId]/rating`, both `teamRoute`.
- **UI** (`CoverageItemActions`, same export and props): "+ Task" (accessible name "Create Task") for anything not
  Covered → dialog with the members (PB-04 `GET /teams/:id`) and an optional due date, loaded when the dialog opens.
  A date-only pick means 11:59 pm that day in the viewer's profile time zone (`endOfDayIso`, DST-safe). Success toast
  with **View on board**; the row then shows **Open task →** (`/board?task=<id>`). Helpful / Not helpful are toggle
  buttons with `aria-pressed`, saved optimistically and reverted if the request fails.

**Decisions / gotchas:**

- The report table's Actions column is narrow (PB-10's file), so the button reads "+ Task" with a screen-reader
  "Create" prefix instead of a long label that overflowed.
- The dialog is mounted only while open: every row renders this slot and the shared `Dialog` uses one fixed heading id.
- A rating can be changed but not cleared (the contract's `rateItemInput` has no null).
