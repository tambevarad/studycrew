## Build

**Service** `src/server/services/activity/service.ts` — ★ `listActivity(teamId, actorId, query): Promise<Page<ActivityDTO>>`:
membership check, newest first by `(createdAt desc, id desc)`, keyset cursor, filters `type`, `entityType`, `actorId`.
Pure `format.ts`: `activitySentence(dto)` → "Krish moved “Slides” to Review" (actor name + summary; "Someone" when
actor deleted) and `groupByDay(items, timeZone, now)` → `[{ label: "Today" | "Yesterday" | "Mon, Oct 19", items }]`.

**Route** `GET /api/v1/teams/[teamId]/activity` (`teamRoute`).

**Page** `/teams/[teamId]/activity` (`SectionHeader` "Activity")
- Filters: member select, category select (Tasks, Meetings, Resources, Team, AI, Milestones, Polls → `entityType`), kept in
  the URL (`?actor=&entity=`).
- Timeline grouped by day (`groupByDay` in viewer tz): avatar, sentence, small type icon, relative time with
  `<time dateTime>` + absolute title.
- **Load more** button (cursor). Empty state: "No activity yet — create a task or schedule a meeting."
- `RecentActivity` server component: last `limit` events as a compact list + "View all" link.

## Acceptance criteria

- AC1: Team actions appear newest first with who did what and when, in my timezone.
- AC2: Filtering by member and by category shows only matching events; the filter survives reload (URL).
- AC3: Load more returns the next page without duplicates or gaps.
- AC4: A non-member gets 403 (sweep) and can't see events.
- AC5: Events whose actor was deleted show "Someone".
- AC6: No serious/critical axe violations.

## Implementation notes (owner fills in)

- **Service** `src/server/services/activity/service.ts`: `listActivity` (★ for PB-12) uses keyset pagination on
  `(createdAt desc, id desc)` with an opaque base64url cursor (`cursor.ts`), so pages stay stable when events share a
  timestamp or new events arrive. A bad cursor returns 400. `listActivityFilterMembers` feeds the member filter.
- **Formatting** lives in `src/components/features/activity/format.ts` (not `src/server`) because the client timeline uses
  it. `groupByDay` groups by calendar day in the **viewer's** time zone (`Intl` with `en-CA` day keys).
- **Page**: filters are URL params (`?actor=&entity=`), validated server-side (unknown values are ignored). The timeline is
  keyed by the filter combination so switching filters remounts it instead of resetting state in an effect.
  "Load more" calls the REST route with the same filters.
- **Category filter** offers each entity type separately ("Members" and "Team settings" are distinct) because the
  contract's `entityType` is a single value.
- **RecentActivity** slot implemented as a Server Component (latest N + "View all activity").
- **Found while testing (fixed in PR "Fix foundation", not here):** Cypress sign-in hit Better Auth's rate limit (429)
  and the shared sidebar failed WCAG contrast on team pages.
- Tests: `tests/unit/activity-format.test.ts` (5), `tests/integration/activity.test.ts` (8), `cypress/e2e/activity.cy.ts` (3).
  Screenshots: `docs/screenshots/PB-09-activity*.png`.
