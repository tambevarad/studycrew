**User story:** As a member, I get in-app notifications for invites, join requests, task assignments, tasks due
within 24 hours, meetings, and polls.

## How notifications get created (already decided)

Other features call `notify()` (`src/server/notifications.ts`) inside their transactions — you don't write those.
You own **reading, marking read, the bell, the page, and the due-soon generator.** The seed creates one notification
for `krish@studycrew.test` and has tasks due within 24 h, so you can build without waiting for anyone.

| Type | Created by | Link |
|---|---|---|

| TASK_ASSIGNED | PB-05 | `/teams/:id/board?task=:taskId` |
| **TASK_DUE_SOON** | **PB-08 (you)** | `/teams/:id/board?task=:taskId` |

## Build

**Service** `src/server/services/notifications/service.ts`
- `generateDueSoonNotifications(userId, now = new Date()): Promise<number>` — tasks where the user is an assignee,
  status ≠ DONE, `dueAt` in `(now, now + DUE_SOON_HOURS h]` → `notify({ type: "TASK_DUE_SOON", title: "“X” is due in 5 h",
  teamId, link, dedupeKey: \`due:${taskId}:${dueAt.toISOString()}\` })`. Re-dating a task produces a new reminder.
- `listNotifications(userId, query, now?)` → `Page<NotificationDTO>`; calls the generator first; cursor = last id with
  `(createdAt, id)` ordering; `unreadOnly` filter.
- `unreadCount(userId, now?)` → generator first, then count.
- `markRead(userId, { ids?, all? })` → only the caller's rows; returns `{ updated }`.

**Routes** `GET /api/v1/me/notifications`, `GET /api/v1/me/notifications/unread-count`, `POST /api/v1/me/notifications/read` (`authedRoute`).

**UI**
- `NotificationBell` (client): bell icon + unread badge (`danger` dot with count, "9+" cap), `aria-label="Notifications, 3 unread"`.
  Fetch `unread-count` on mount, every 60 s (TanStack Query `refetchInterval` or `setInterval`), and on window focus.
  Click → `/notifications`.
- `/notifications` (`PageHeader` "Notifications", action **Mark all as read**): tabs All / Unread; grouped "Today",
  "This week", "Earlier"; each item: type icon, title, body, team name, relative time with absolute tooltip; unread rows
  have a `brand` left border + "Unread" sr-only text. Clicking marks it read and navigates to `link`. "Load more"
  pagination. Empty state "You're all caught up."

## Acceptance criteria

- AC1: Given a task assigned to me due in 5 hours, when I open notifications, then I see "“X” is due in 5 h" exactly once even after reloading.
- AC2: Tasks that are DONE, overdue, due in > 24 h, or assigned to someone else produce no due-soon notification.
- AC3: The bell shows my unread count and updates within 60 s of a new notification.
- AC4: Clicking a notification marks it read and opens its link; "Mark all as read" clears the badge.
- AC5: I can't read or mark another user's notifications (only my rows change).
- AC6: Pagination returns stable pages without duplicates.
- AC7: No serious/critical axe violations; the badge count is announced to screen readers.

## Required tests

- Integration `tests/integration/notifications.test.ts`: generator windows + dedupe (AC1, AC2, re-dated task), list/unread/markRead routes, AC5, AC6 (use fixed `now`).
- E2E `cypress/e2e/notifications.cy.ts`: log in as `krish` → bell shows count → open page → click item → badge decreases → mark all read; a11y.

## Implementation notes (owner fills in)

**Built (Oct 22, Krish + Claude Code):**

- **Service** `src/server/services/notifications/service.ts`: `generateDueSoonNotifications(userId, now)` (assigned,
  not Done, `dueAt` in `(now, now + 24 h]`, only teams the user still belongs to; title "“X” is due in 5 h" or "… in
  under an hour"; body "Due Wed, Oct 28, 3:00 PM" in the user's zone; `dedupeKey = due:<taskId>:<dueAt ISO>`),
  `listNotifications` (generator first; newest first by `(createdAt, id)`; cursor = last id; a cursor that isn't
  yours → 400), `unreadCount` (generator first), `markRead` (only the caller's unread rows), and
  `notificationTeamNames` (see below).
- **Routes** `GET /api/v1/me/notifications`, `GET …/unread-count`, `POST …/read` (`authedRoute`).
- **Bell** (`NotificationBell`, same export, no props): `danger` badge with "9+" cap, `aria-label="Notifications, 3
  unread"`. Refreshes on mount, every 60 s (`setInterval`), on window focus, and on a `studycrew:notifications-changed`
  window event that the page fires after marking read, so the badge updates immediately. TanStack Query wasn't used
  because the frozen layout has no `QueryClientProvider`.
- **Page** `/notifications`: `PageHeader` with **Mark all as read**; All / Unread tabs (links, `?filter=unread`);
  groups Today / This week / Earlier by the viewer's calendar day; each item has a type icon, title, body, team name,
  and a relative time with the absolute time as a tooltip. Unread rows have a `brand` left border, bold title, and
  sr-only "Unread:". Clicking marks the item read, then opens its link. "Load more" pagination, `EmptyState` "You're all
  caught up.", plus `loading.tsx` / `error.tsx`.

**Decisions / gotchas:**

- `NotificationDTO` has `teamId` but no team name, and contracts are frozen. The page resolves names on the server
  with `notificationTeamNames(userId)` across all of the user's notifications, so "Load more" pages have names too.
- The server passes `nowIso` so relative times match between server render and hydration.
- **`cypress/e2e/notifications.cy.ts` needs PB-05's task routes** (it creates tasks due in 2 h assigned to Krish to get
  fresh reminders), so merge PB-05 first. The seed has only one notification for Krish, which isn't enough for repeatable
  tests. It gets the user id from Better Auth's `/api/auth/get-session` so it doesn't depend on PB-02, and deletes its
  tasks at the end.

**Tests:** `tests/unit/notifications.test.ts` (badge cap, accessible name, grouping by the viewer's day),
`tests/integration/notifications.test.ts` (generator windows incl. exact edges, dedupe, re-dated tasks, left teams;
list/unread/markRead routes; AC5; AC6 stable pages with equal timestamps; fixed `now`), `cypress/e2e/notifications.cy.ts`
(bell updates within one fake-timed 60 s poll, reminder appears once after reload, click → read + link, Unread tab,
Mark all as read clears the badge, axe).
