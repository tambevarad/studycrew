**User story:** As a member, I get in-app notifications for invites, join requests, task assignments, tasks due
within 24 hours, meetings, and polls.

## How notifications get created (already decided)

Other features call `notify()` (`src/server/notifications.ts`) inside their transactions — you don't write those.
You own **reading, marking read, the bell, the page, and the due-soon generator.** The seed creates one notification
for `krish@studycrew.test` and has tasks due within 24 h, so you can build without waiting for anyone.

## Build

**Service** `src/server/services/notifications/service.ts`
- `generateDueSoonNotifications(userId, now = new Date()): Promise<number>` — tasks where the user is an assignee,
  status ≠ DONE, `dueAt` in `(now, now + DUE_SOON_HOURS h]` → `notify({ type: "TASK_DUE_SOON", title: "“X” is due in 5 h",
  teamId, link, dedupeKey: \`due:${taskId}:${dueAt.toISOString()}\` })`. Re-dating a task produces a new reminder.
- `listNotifications(userId, query, now?)` → `Page<NotificationDTO>`; calls the generator first; cursor = last id with
  `(createdAt, id)` ordering; `unreadOnly` filter.
- `unreadCount(userId, now?)` → generator first, then count.
- `markRead(userId, { ids?, all? })` → only the caller's rows; returns `{ updated }`.

**Routes** `GET /api/v1/me/notifications`, `GET /api/v1/me/notifications/unread-count`, `POST /api/v1/me/notifications/read` (`authedRoute`).

**UI**
- `NotificationBell` (client): bell icon + unread badge (`danger` dot with count, "9+" cap), `aria-label="Notifications, 3 unread"`.
  Fetch `unread-count` on mount, every 60 s (TanStack Query `refetchInterval` or `setInterval`), and on window focus.
  Click → `/notifications`.
- `/notifications` (`PageHeader` "Notifications", action **Mark all as read**): tabs All / Unread; grouped "Today",
  "This week", "Earlier"; each item: type icon, title, body, team name, relative time with absolute tooltip; unread rows
  have a `brand` left border + "Unread" sr-only text. Clicking marks it read and navigates to `link`. "Load more"
  pagination. Empty state "You're all caught up."

## Acceptance criteria

- AC1: Given a task assigned to me due in 5 hours, when I open notifications, then I see "“X” is due in 5 h" exactly once even after reloading.
- AC2: Tasks that are DONE, overdue, due in > 24 h, or assigned to someone else produce no due-soon notification.
- AC3: The bell shows my unread count and updates within 60 s of a new notification.
- AC4: Clicking a notification marks it read and opens its link; "Mark all as read" clears the badge.
- AC5: I can't read or mark another user's notifications (only my rows change).
- AC6: Pagination returns stable pages without duplicates.
- AC7: No serious/critical axe violations; the badge count is announced to screen readers.

## Required tests
