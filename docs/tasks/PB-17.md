## Implementation notes (owner fills in)

**Dev: NFR-01/02/03 scripts (Nov 3).** Results are **pending the final run** after PB-14, PB-15, PB-16 merge, so the
numbers cover every page. Nothing has been run against staging yet.

- **NFR-01** `perf/seed-load.ts` + `perf/load.js` (k6). See `perf/README.md` for the order.
  - The seeder only adds data (10 users, 50 private teams in `LOAD 9000`, 2,000 tasks, 300 meetings) and is idempotent.
    It never calls `prisma/seed.ts`. Tested twice on the local DB: first run +10 users / +50 teams / +2,000 tasks; second
    run changed nothing; demo teams untouched.
  - Better Auth allows ~3 sign-ins / 10 s per IP, so k6 signs the 10 load users in once in `setup()` (honouring
    `X-Retry-After`) and the 100 VUs share those sessions.
  - Thresholds: p95 < 800 ms, errors < 1 % on `kind:api` requests only (sign-in excluded).
  - k6 itself hasn't been run yet (not installed locally; the final run is in `nfr.yml`).
- **NFR-02** `security/`: `npm-audit.mjs` (fails on high/critical), `scan-client-bundle.mjs`, `zap-rules.tsv`.
  - The bundle scan fails on key-shaped strings, or on the value of any server-only env var that is set, and prints the
    kind only. Proven with a planted fake key and env value.
  - Env-var names are warnings only: Better Auth's client SDK contains a `BETTER_AUTH_SECRET` getter, which is not a leak.
- **NFR-03** `lighthouserc.json` + `perf/lhci-login.cjs` (signs in once; a11y ≥ 0.9 is an error, perf/best-practices
  are warnings). `cypress/e2e/a11y-sweep.cy.ts` covers 19 pages and runs in every CI `e2e`. **Its first run found D-05**
  (Members page "Make leader" label in name), fixed in #51. This PR is stacked on #51.
- `.github/workflows/nfr.yml`: `workflow_dispatch` only, with one checkbox per check (audit, bundle scan, ZAP, Lighthouse,
  k6). The load job needs the repo secret `LOAD_TEST_PASSWORD`.
