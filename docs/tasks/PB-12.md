**User story:** As a member, I can see a dashboard with progress, overdue work, meetings, and workload.

## Files you own

`src/server/services/dashboard/**`, `src/app/api/v1/teams/[teamId]/dashboard/**`, `src/app/(app)/teams/[teamId]/page.tsx`,
`src/app/(app)/dashboard/**` (replace the foundation version), `src/components/features/dashboard/**`, tests `dashboard*`.

## Build

- `getTeamDashboard(teamId, actorId, now = new Date()): TeamDashboardDTO` — completion % (DONE / all), overdue tasks,
  due-soon (24 h), next 5 meetings (PB-06 `listMeetings`), milestones with % (read `milestone` + task counts), open
  tasks per member (not DONE; overdue count). Reads tables directly or via exported services; writes nothing.
- Route `GET /api/v1/teams/[teamId]/dashboard`.
- Team overview page (`/teams/[teamId]`): stat tiles (completion %, open, overdue, next meeting) — **graphics + text**:
  Recharts donut for completion with the number in the centre, bar chart for open tasks per member with a visually
  hidden table equivalent; overdue list (danger), due soon (warning), upcoming meetings, milestone progress bars,
  `<RecentActivity teamId limit={5} />`. Empty team → guidance ("Add tasks on the Board to see progress here").
- Personal home `/dashboard`: "My tasks" across teams (due soon first), "My next meetings", my teams grid (keep the
  existing cards), pending invites count with link.

## Acceptance criteria

- AC1: With 7 tasks of which 2 are DONE the dashboard shows 29% complete.
- AC2: Overdue = dueAt < now and not DONE; each overdue task links to the board.
- AC3: Workload shows each member's open and overdue counts, including members with 0.
- AC4: Charts have text equivalents; no serious/critical axe violations.
- AC5: Personal home lists only my assigned, not-DONE tasks across my teams.

## Required tests

Integration for `getTeamDashboard` with fixed `now` (AC1–AC3, AC5); E2E: open the seeded team overview, check tiles; a11y.

## Implementation notes (owner fills in)

**Built (Nov 1, Krish + Claude Code):**

- **Service** `src/server/services/dashboard/service.ts`, read-only (writes nothing):
  - `getTeamDashboard(teamId, actorId, now = new Date())` returns `TeamDashboardDTO`. It reuses PB-05's `taskInclude` +
    `toTaskDTO(row, now)`, PB-06's `listMeetings` (window: now → now + 90 days, first 5; a meeting already in progress
    still counts as upcoming), PB-13's `listMilestones` (its `percent`), and `percent()` from
    `components/features/milestones/progress.ts` for the completion %, so the rounding matches the Milestones tab.
  - For the personal home: `listMyOpenTasks(userId, now)` (my assigned, not-Done tasks in teams I'm still a member of,
    soonest due first, no date last) and `listMyUpcomingMeetings(userId, now, limit = 5)` (meetings of my teams that
    haven't ended).
  - Pure rules in `rules.ts`: `isOverdueAt` (due < now, not Done), `isDueSoonAt` (now ≤ due ≤ now + 24 h, not Done),
    `byDueSoonest`, and `workloadByMember`. The workload lists every current member (0 included), skips Done tasks and
    ex-members, counts a task once per assignee, and sorts by name.
- **Route** `GET /api/v1/teams/[teamId]/dashboard` with `teamRoute` (the authorization sweep covers it). It is already
  in `api.md`, so no new endpoint was added.
- **Team overview** (`/teams/[teamId]`):
  - Four tiles: a completion donut with the % in the centre plus "N of M tasks done", open, overdue (danger), and the
    next meeting.
  - Panels: overdue (each task links to `board?task=<id>` with "Overdue by …"), due in the next 24 h, open tasks per
    member, upcoming meetings, milestone progress bars (`role=progressbar` with `aria-valuetext`), and
    `<RecentActivity teamId limit={5} />`.
  - A team with no tasks shows "No tasks yet" with a link to the board.
  - Loading and error states live in the page: a `Suspense` skeleton (`role=status`), and an `Alert` with "Try again"
    if the query fails. A `[teamId]/loading.tsx` or `error.tsx` would wrap every team tab and isn't PB-12's file.
- **Personal home** (`/dashboard`): "Hi, {first name}", the pending-invites alert linking to `/teams`, "My tasks (n)"
  with team names, "My next meetings", and the existing "My teams" cards (or the existing empty state). Also
  `loading.tsx` and `error.tsx`. There is no contract DTO for this page, so it is composed in the Server Component from
  `TaskDTO` / `MeetingDTO` plus team names from `listMyTeams`.

**Charts and accessibility (AC4):**

- **Donut:** Recharts `PieChart` (success-600 on a success-100 track). The ring is decorative (`aria-hidden`); the % in
  the centre and the "N of M tasks done" line are real text.
- **Workload:** a horizontal stacked `BarChart`, with overdue (danger-600) at the baseline, then open-on-time
  (brand-600), the total at the bar end, an HTML legend, and a hover tooltip. A visually hidden `<table>` (caption
  "Open and overdue tasks per member") carries the same numbers. Colours were checked with the dataviz palette
  validator (CVD ΔE 29.8, ≥ 3:1 on white).
- Both charts render client-only (`useHydrated` = `useSyncExternalStore`), so Recharts' generated ids can't cause a
  hydration mismatch. Before hydration the box keeps its size, and the text equivalents are server-rendered.
- Inside `aria-hidden` nothing may be focusable, but Recharts makes the svg and the pie focusable by default. Hence
  `accessibilityLayer={false}` on both charts and `rootTabIndex={-1}` on the pie; axe `aria-hidden-focus` caught it.
- Recharts drops zero-width bars and their labels, so a member with 0 open tasks (or with all open tasks overdue)
  showed no total. The on-time bar now has a pass-through `shape`, which keeps the "0" label.
- All dates are formatted on the server with the `formatToParts` helpers from `meetings/format.ts` and `dueLabel`; no
  whole-string `Intl` runs in client render. No client component imports `src/server/**`.

**Decisions / gotchas:**

- A non-member opening `/teams/<id>` gets the layout's "ask to join" message. The overview catches `FORBIDDEN` /
  `NOT_FOUND` and renders nothing, instead of throwing and logging an error for every such visit.
- **Layering wart:** a service imports `percent()` from `components/features/milestones/progress.ts`. It's a pure
  function, reused so the rounding is the same everywhere. It's the same backwards import as §2 of
  `docs/contract-requests/PB-06-dialog-ids-and-date-helpers.md` (meeting date helpers → `src/lib`); if the tech lead
  moves those, `progress.ts` should move with them.
- `Panel` takes `level` (h2 on the personal home, h3 under the overview's h2) so the heading order stays valid.
