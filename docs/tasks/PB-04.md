## Build

**Service** `src/server/services/teams/service.ts` (all writes in transactions with `logActivity` / `notify`):
- `createTeam(actorId, input)` → creator LEADER; `inviteCode` = 10 random url-safe chars (`crypto.randomBytes`), retry on collision.
- `searchTeams(viewerId, { course, q })` → open teams in that course + any team the viewer is in for that course,
  with `memberCount`, `myRole`, `hasPendingRequest`; name filter `q` is case-insensitive contains. Closed teams the viewer isn't in are hidden.
- `getTeam(teamId, viewerId)` → `TeamDetailDTO` (members sorted leaders first, then joinedAt).
- `updateTeam(teamId, actorId, input)` leader only.
- `inviteByEmail(teamId, actorId, { emails })` leader only → creates invites (skip emails of current members and
  emails with a live pending invite), `INVITE_SENT`; `notify(TEAM_INVITE)` for invitees who already have accounts,
  link `/teams`.
- `rotateInviteCode(teamId, actorId)` leader only.
- `joinByCode(code, userId)` → idempotent; 404 bad code; 409 team full; `MEMBER_JOINED`.
- `listMyInvites(userId)` (by email; pending, not expired), `acceptInvite(inviteId, userId)` (email must match → else 403),
  `declineInvite`.
- `requestToJoin(userId, { teamId, message })` → 409 if member/pending/full; 403 if team closed; `JOIN_REQUESTED`;
  `notify(JOIN_REQUEST)` to leaders, link `/teams/<id>/members`.
- `listJoinRequests(teamId, actorId)` leader only; `listMyJoinRequests(userId)`; `cancelJoinRequest(requestId, userId)`.
- `decideJoinRequest(requestId, actorId, { decision })` → actor must lead that team; APPROVE adds member (409 if full),
  `JOIN_APPROVED` + `MEMBER_JOINED`; DECLINE → `JOIN_DECLINED`; `notify(JOIN_DECISION)` to requester.
- `changeRole(teamId, actorId, userId, { role })` leader only; can't demote the last leader (409).
- `removeMember(teamId, actorId, userId)` leader removes anyone but themselves-if-last-leader; a member may remove
  themselves (leave) → `MEMBER_LEFT` vs `MEMBER_REMOVED`.

**Routes** — exactly the table in `api.md` § PB-04. Team routes use `teamRoute` (`leaderOnly` where stated).

**Pages**
- `/teams` ("Find teams"): course code search (defaults to the first course on my profile; `?course=` prefilled from
  links), optional name filter, results as cards (name, course, description, member count, "Open"/"Full", my status:
  Member / Request pending / **Ask to join** button → dialog with optional message). Above results: "Invitations"
  (accept/decline) and "My requests" (cancel). Empty state: "No open teams for CSE 6324 yet — create one."
- `/teams/new`: form (name, course code with hint, description, "Listed in course search" toggle) → redirect to the new
  team's members page with an Alert "Share this link to invite teammates".
- `/join/[inviteCode]`: shows team name + course, "Join team" button (or "You're already a member → Open team").
- `/teams/[teamId]/members` (`SectionHeader`): member list with role badges; leader controls (make leader / make
  member / remove with ConfirmDialog); "Invite link" card with copy button (and "Reset link" for leaders); "Invite by
  email" (leader); "Join requests" list with Approve/Decline (leader); "Leave team" for everyone (ConfirmDialog; blocked
  with an explanation for the last leader).

## Acceptance criteria

- AC1: When I create a team for "cse6324", then it's stored as "CSE 6324", I'm its leader, it appears in my sidebar, and activity shows "created the team".
- AC2: When another user opens `/join/<code>` and clicks Join, they become a member; opening it again is harmless.
- AC3: Searching "CSE 6324" lists open teams in that course with member counts; closed teams appear only to their members.
- AC4: A non-member can send one join request; a second one returns 409; leaders get a JOIN_REQUEST notification.
- AC5: A leader approves → requester becomes a member and is notified; a non-leader trying to approve gets 403.
- AC6: Email invite to an existing user creates a TEAM_INVITE notification; the invitee can accept it from `/teams`; someone else can't accept it (403).
- AC7: A full team (8) rejects joins, approvals, and invites with a clear 409 message.
- AC8: The last leader can't leave or be demoted (409 with explanation).
- AC9 (NFR-02): every `teams/[teamId]/*` route returns 403 to non-members (authorization sweep passes).
- AC10: Pages have no serious/critical axe violations.

## Implementation notes (owner fills in)

**Built (Oct 23, Dev + Claude Code):**

- **Service** `src/server/services/teams/service.ts`: every function in the spec, plus page helpers `getInvitePreview`
  (for `/join/<code>`), `myCourses`, `myRoleIn`. Pure rules in `rules.ts`: invite code (10 URL-safe chars from
  `crypto.randomBytes`, retried on a unique collision), email normalization (trim, lowercase, de-duplicate), invite expiry
  (14 days), "full" (8), member sort (leaders first, then join date), last-leader check.
- **Routes**: exactly the api.md § PB-04 table (17 handlers in 12 files). Team routes use `teamRoute` (`leaderOnly` for
  PATCH team, invites, invite-code, join-requests list, role change). Join links, invites, and join requests live outside
  `teams/[teamId]` because the caller isn't a member yet. Decisions check "leader of that team" in the service (AC5).
- **Pages**: `/teams` (Find teams: plain GET search form with course + name, profile courses as quick links, Invitations,
  My requests, result cards with Open/Full, member count, and Member / Request pending / **Ask to join** dialog),
  `/teams/new`, `/join/[inviteCode]` (invalid link / already a member / full / Join), `/teams/[teamId]/members`
  (roster with role badges, leader controls, invite link card with Copy + Reset, invite by email, join requests with the
  requester's message, Leave team blocked with an explanation for the last leader).

**Decisions / gotchas:**

- **Concurrency (AC4, AC7):** the schema has no partial unique index for "one PENDING request" and no limit on members.
  Every write that can add a member or a pending request, or remove or demote a leader, locks the team row
  (`SELECT … FOR UPDATE`) inside its transaction and re-checks there. An integration test fires 3 simultaneous joins at a
  7-member team: exactly one succeeds and two get 409. A second test fires 2 duplicate requests: only one is stored.
- **Joining tidies up:** joining by any path (link, invite, approval) cancels that user's other PENDING request for the
  team and marks their live invite accepted, so leaders never see stale requests from members.
- **Declining an invite** sets `revokedAt` (the schema has no `declinedAt`). It simply stops being live.
- **Closed teams** are hidden from search and reject join requests (403), but an invite link or email invite still works,
  because those are explicit invitations.
- **Contract request** `docs/contract-requests/PB-04-update-team-isopen-default.md`: `updateTeamInput` (`.partial()` of the
  create schema) still applies `isOpen: true` by default, so a rename would re-list a closed team. The PATCH route only
  passes `isOpen` when the body sends it. There's a test for it.
- **Removing a member leaves their task assignments** (PB-05 owns `task_assignee`, and there's no exported function to
  unassign). PB-08 already ignores tasks in teams you've left. Follow-up: ask Krish for an exported
  `unassignFromTeamTasks(teamId, userId, tx)` in `services/tasks` and call it from `removeMember`.
- The create form uses `noValidate` so the server's specific field messages show under the fields, instead of the
  browser's generic bubbles.
- `cypress/e2e/teams.cy.ts` waits for success toasts to close before axe checks. #29 fixes the colors, but a toast
  still fails axe while it fades in (~350 ms), so the wait stays. Its `after()` restores the seed state (outsider's pending request to Query Optimizers), so reruns and other
  specs are unaffected.
- The shared `Dialog` uses a fixed heading id, so dialogs are mounted only while open (one per page).

**Tests:** `tests/unit/teams.test.ts` (11: rules + client helpers), `tests/integration/teams.test.ts` (24: every service
function and route, AC1–AC9, both concurrency cases), `cypress/e2e/teams.cy.ts` (3: create → link → join; request →
approve; last leader can't leave; axe on all four pages and the dialog). Full Cypress suite 29/29 locally; the PB-04 spec
passed 5/5 runs with retries off.
