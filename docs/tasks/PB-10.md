**User story:** As a member, I can run the AI Coverage Check on assignment instructions and our draft, and see each
requirement marked Covered, Partial, or Missing with evidence.

This is the feature the course grades as "the AI-enabled product feature" (progress report §6.1). Its evaluation
(PB-16) depends on the prompt and quote verification you build here.

## Build

**AI module** (`src/server/ai/`)
- `prompts.ts`: `PROMPT_VERSION = "v1"`, system + user prompts for (1) extraction — "list each distinct, checkable
  requirement as a short imperative sentence; merge duplicates; max 25" — and (2) checking — "for each requirement decide
  COVERED / PARTIAL / MISSING; quote the draft **word for word** (≤ 300 chars) as evidence or null; one-line reason; one
  concrete next step that tells the student what to add, never write the content". Include the work type.
- `providers/openai.ts`, `providers/gemini.ts`, `providers/claude.ts`: implement `CoverageModel` with `generateObject`
  and strict Zod schemas (`z.object({ requirements: z.array(z.string()).max(25) })`, and an items array schema).
  Models from env: `OPENAI_MODEL` (default `gpt-5.4-mini`), `GEMINI_MODEL`, `CLAUDE_MODEL`. Pass `abortSignal`.
  Register them in `factories` in `src/server/ai/index.ts`.
- `quotes.ts` (pure, unit-tested): `normalizeForMatch(s)` (collapse whitespace, unify curly/straight quotes and dashes,
  trim, lower-case) and `verifyQuote(quote, draft): boolean` (normalized substring, quote ≥ 3 words).
- `scoring.ts` (pure): `scoreItems(items)` → `round((covered + 0.5 × partial) / n × 100)`, 0 when n = 0;
  `countByStatus(items)`.

**Service** `src/server/services/coverage/service.ts`
- `runCoverageCheck(teamId, actorId, input, deps = { model: getCoverageModel(), now: new Date() })`:
  1. membership; 2. rate limit: ≥ `MAX_RUNS_PER_USER_PER_DAY` reports by this author since 00:00 UTC → 429 "You've used
  today's 10 checks. Try again tomorrow."; 3. `AbortSignal.timeout(AI_TIMEOUT_MS)` around both model calls;
  4. verify each quote → `evidenceVerified`; unverified quote ⇒ quote kept but COVERED downgraded to PARTIAL with reason
  prefixed "Couldn't find this quote in your draft — "; 5. score; 6. persist report + items in one transaction,
  `COVERAGE_RUN` activity ("ran an AI check on “Title” (score 72)").
  On timeout/provider error: persist a FAILED report (`errorMessage`, `latencyMs`, no items) and throw
  `errors.upstream("The AI service didn't respond in time. Nothing was lost — try again in a minute.")`.
  Never log `instructions`/`draft`.
- `listReports(teamId, actorId)`, `getReport(teamId, actorId, reportId)` (`canDelete` = author or leader),
  `deleteReport(teamId, actorId, reportId)` → hard delete (cascade items), `COVERAGE_DELETED`; 403 for others.

**Routes** exactly as `api.md` § PB-10 (`teamRoute`). Set `export const maxDuration = 60` on the POST route (Vercel).

**Pages**

## Acceptance criteria

- AC1: Given the proposal's psychology example (benefits covered, drawbacks missing), the mock returns Drawbacks as not Covered, and the report shows it with a suggestion.
- AC2: Every stored evidence quote is either verified against the draft or flagged; an unverified COVERED becomes PARTIAL.
- AC3: Without the consent box the request is rejected (400) and nothing is sent to the provider.
- AC4: The 11th run in a UTC day returns 429 with a friendly message.
- AC5: If the provider times out or errors, the user sees a clear message within 30 s, a FAILED report is recorded, and the rest of the app keeps working.
- AC6: Instructions > 15,000 or draft > 30,000 chars → 400 with the limit in the message.
- AC7: The author or a leader can permanently delete a report; other members get 403.
- AC8: Score = (covered + 0.5 × partial) / n × 100, rounded.
- AC9: Provider is selected by `AI_PROVIDER`; tests always use the mock; switching to OpenAI needs no code change.
- AC10: No serious/critical axe violations; status is shown with text, not only color.

## Implementation notes (owner fills in)

**Flow (`runCoverageCheck`)**: membership → daily limit (10 per author since 00:00 UTC, across all teams, FAILED runs
included) → one `AbortSignal.timeout(30 s)` shared by both model calls → extract (≤ 25 requirements) → check →
`alignItems` → `verifyItems` → `scoreItems` → one transaction for report + items + `COVERAGE_RUN`. Step 1's list is the
source of truth (review of #34): each requirement takes the model item with the same text, or the same position when the
counts match; a requirement the model skipped becomes MISSING ("The AI didn't assess this requirement…"), so a short
answer can't inflate the score. Instructions with no extractable requirement still reach the provider, so that run is
saved as FAILED (counts toward the limit) and returns 400. Reports are stamped with the same `now` the limit uses. Consent is enforced by the route's Zod
schema (`consent: z.literal(true)`), so a request without it never reaches the service or the model (AC3).

**Timeout**: each model call is wrapped in `untilAborted(promise, signal)`, which rejects when the signal fires even if
the provider ignores it (tested with a fake that never resolves). Timeouts and provider errors save a FAILED report
(`errorMessage`, `latencyMs`, `score: null`, no items, no activity) and throw 502 `UPSTREAM`. Timeout uses the spec's
message; other provider errors say "couldn't finish this check" (a missing key is not a timeout). Only provider/model and
the error *class* are logged, never instructions or draft (an integration test checks the log).

**Quote verification (AC2)**: `verifyQuote` normalizes Unicode (NFKC), curly/straight quotes, dash variants, the "…"
character, whitespace, and case, then requires a ≥ 3-word substring of the draft. Quotes > 300 chars are cut at a word
boundary first (`clampQuote`); a prefix of a verbatim quote is still verbatim. Unverified quote ⇒ kept, flagged, and
COVERED → PARTIAL with "Couldn't find this quote in your draft — " prefixed; PARTIAL/MISSING keep their status.

**Providers (AC9)**: one `SdkCoverageModel` (AI SDK v7 `generateText` + `Output.object`, `instructions` instead of
`system` — `generateObject` is deprecated in v7) plus thin `openai.ts` / `gemini.ts` / `claude.ts`. Defaults:
`gpt-5.4-mini` (strict JSON schema, `reasoningEffort: "low"`), `gemini-3.5-flash`, `claude-haiku-5-5`; override with
`OPENAI_MODEL` / `GEMINI_MODEL` / `CLAUDE_MODEL`. `maxRetries: 1`. Schemas use nullable (not optional) fields for
OpenAI strict mode. **The adapter refuses to call the provider when its API key env var is empty**: the SDK otherwise
treats `OPENAI_API_KEY=""` (what `.env.example` ships) as a key and sends the text to OpenAI before failing with 401.

**Extra beyond the spec** (small, all tested): `remainingRunsToday()` for "N of 10 checks left today";
`activeProvider()` so the consent text names the real provider (it says "built-in test model" under the mock);
instructions with no extractable requirement → 400 and nothing saved.

**UI**: both pages are Server Components; dates are formatted on the server with `meetings/format.ts`; counters use
a regex thousands separator instead of `toLocaleString` (hydration). Form uses `noValidate`, shows server field
errors under fields and 429/502 inline (no toast), and clears a field's error when it changes. Status filter is a set
of links (`?status=MISSING`), default "All" sorted Missing → Partial → Covered. The ConfirmDialog is mounted only while
open. `<CoverageItemActions teamId item />` renders in an "Actions" column of every row.

**Tests**: unit `coverage-quotes`, `coverage-scoring`, `coverage-providers` (real adapters on the SDK's
`MockLanguageModelV4`; empty-key refusal); integration `coverage.test.ts` (23 tests, AC1–AC8, every service function
and route); E2E `coverage.cy.ts` (3 tests + optional screenshot capture). Service line coverage 96%.
